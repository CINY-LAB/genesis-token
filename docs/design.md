# GENESIS TOKEN 기획서 (Node.js + Web UI 재구현용 프롬프트)

## 0. 작업 지시 (AI에게)

- 이 문서는 Python(Termux 터미널)으로 만들던 방치형 채굴 게임의 기획 전체임.
- 이번 작업은 이 기획을 Node.js 기반 웹 게임으로 다시 만드는 것임.
- 새 프로젝트를 처음부터 만들지 말 것.
- 내가 이전에 만들던 비슷한 게임 프로젝트가 있음. 그 코드를 이 기획 방식으로 변형해서 다시 만들 것.
- 비유하면 집을 새로 짓는 게 아니라, 기존 집의 뼈대는 살리고 방 구조를 새 설계도대로 바꾸는 리모델링임.

**기존 프로젝트 변형 순서**

1. 기존 프로젝트의 폴더 구조, 실행 방법, 사용 중인 라이브러리를 먼저 파악할 것.
2. 기존 기능과 이 기획서를 비교한 표(유지 / 변형 / 삭제 / 신규)를 먼저 보여줄 것.
3. 내가 표를 확인한 뒤에 코드 수정을 시작할 것.
4. 기존 프로젝트의 코드 스타일, 폴더 규칙, 빌드 방식은 최대한 유지할 것.
5. 기존 코드와 이 기획이 충돌하면 이 기획서를 우선함.
6. 기존 저장 데이터와 호환은 필요 없음.

**공통 규칙**

- UI 문구와 코드 주석은 영어로 작성할 것.
- 게임 로직과 화면(UI) 코드는 분리할 것.
- 모든 밸런스 수치는 설정 파일 한 곳(예: `config.js`)에 모을 것.
- 쥬얼 드롭 확률은 설정값 하나로 테스트 배율(x10)을 켜고 끌 수 있게 할 것.
- 개발 중 테스트용 치트(토큰 지급, 쥬얼 지급)는 개발 모드에서만 보이게 할 것.
- 키보드만으로 모든 조작이 가능해야 함. 마우스 클릭도 같이 지원할 것.

## 1. 게임 개요

- 장르: 방치형 + 타자 채굴 게임.
- 제목: GENESIS TOKEN.
- 핵심 재화: 토큰.
- 주 콘텐츠: 랜덤 문자열을 따라 입력하는 타자 채굴.
- 보조 수입: 자동 채굴 (짬짬이 쌓이는 덤 수준).
- 최종 목표: 모든 업그레이드 완료 후 Genesis Token 구매.
- 세계관: 지금까지 모은 토큰은 원래 하나였던 Genesis Token의 부스러기임.
- 비유하면 자동 채굴은 통장 이자, 타자 채굴은 월급임. 이자만으로는 끝까지 갈 수 없음.

**플레이 시간 목표**

| 구분 | 목표 |
|---|---|
| 빠른 플레이어 | 약 3일 |
| 보통 플레이어 | 약 7일 |

- 가정: 하루 8시간 게임을 켜두고, 그중 1시간(보통) 또는 2시간(빠름) 타자 채굴을 함.
- 게임이 꺼져 있던 시간의 보상(오프라인 보상)은 없음.
- 시뮬레이션 기준 토큰 수입의 약 53%가 타자 채굴, 약 47%가 자동 채굴에서 나옴 (목표 5:5, tools/sim.js 80회, 타자 1시간/일 기준).

## 3. 자동 채굴 (Auto Miner)

- 기존 "토큰 레벨" 개념을 "자동 채굴 레벨"로 변경함.
- 최대 레벨 50.

| 항목 | 값 |
|---|---|
| 채굴 간격 | 10 - 0.06 x (레벨 - 1)초, 최소 2초 (Sapphire로 추가 단축) |
| 1회 채굴량 | 0.5 + 0.15 x (레벨 - 1) |
| 레벨업 비용 | 300 x 1.14^(레벨 - 1) |

| 레벨 | 1회 채굴량 | 채굴 간격 | 다음 레벨 비용 |
|---|---|---|---|
| 1 | 0.5 | 10.0초 | 300 |
| 10 | 1.9 | 9.5초 | 975 |
| 20 | 3.4 | 8.9초 | 3,616 |
| 30 | 4.9 | 8.3초 | 13,407 |
| 40 | 6.4 | 7.7초 | 49,706 |
| 49 | 7.7 | 7.1초 | 161,641 |

- 1~50 전체 비용 합계 약 131만 토큰.
- 경과 시간을 누적했다가 간격이 찰 때마다 1회씩 지급할 것.
- 예: 기기가 잠깐 멈춰 30초가 한 번에 지나가도 3회 지급됨.

## 4. 타자 채굴 (Mine)

- 화면에 랜덤 문자열이 나오면 똑같이 입력 후 Enter로 제출함.
- 정답이면 랜덤 토큰 지급 + 확률로 쥬얼 1개 획득.
- 오답이면 보상 없이 새 문자열이 나옴.
- 광산 레벨이 오를수록 문자열이 어려워지고, 보상과 쥬얼 확률이 오름.
- 광산 최대 레벨 10.
- 광산 레벨업은 Mine 화면에서 토큰으로 함.

**광산 레벨표**

| Lv | 길이 | 문자 구성 | 토큰 보상 | 쥬얼 확률 | 다음 레벨 비용 |
|---|---|---|---|---|---|
| 1 | 4 | 소문자 | 12~24 | 2.0% | 2,000 |
| 2 | 4 | 소문자 | 19~37 | 2.2% | 4,600 |
| 3 | 5 | 소문자+숫자 | 29~58 | 2.4% | 10,580 |
| 4 | 5 | 소문자+숫자 | 45~89 | 2.6% | 24,334 |
| 5 | 6 | 대소문자 | 69~139 | 2.8% | 55,968 |
| 6 | 6 | 대소문자 | 107~215 | 3.0% | 128,727 |
| 7 | 7 | 대소문자+숫자 | 166~333 | 3.2% | 296,072 |
| 8 | 7 | 대소문자+숫자 | 258~516 | 3.4% | 680,965 |
| 9 | 8 | 대소문자+숫자, 헷갈리는 글자 포함 | 400~800 | 3.6% | 1,566,220 |
| 10 | 8 | 대소문자+숫자, 헷갈리는 글자 포함 | 620~1,239 | 3.8% | MAX |

- 보상 기준값 = 12 x 1.55^(Lv - 1), 보상 범위 = 기준값 ~ 기준값 x 2.
- 레벨업 비용 = 2,000 x 2.3^(Lv - 1).
- 헷갈리는 글자 예시: `0/O`, `1/l/I`.
- 테스트 모드에서는 쥬얼 확률 x10.

**쥬얼 등급 확률 (쥬얼이 나왔을 때)**

| 광산 Lv | Normal | Rare | Unique | Legendary |
|---|---|---|---|---|
| 1 | 80% | 17% | 3% | 0% |
| 3 | 74% | 19.4% | 5.4% | 1.2% |
| 5 | 68% | 21.8% | 7.8% | 2.4% |
| 7 | 62% | 24.2% | 10.2% | 3.6% |
| 10 | 53% | 27.8% | 13.8% | 5.4% |

- 공식: Normal 80 - 3(Lv-1), Rare 17 + 1.2(Lv-1), Unique 3 + 1.2(Lv-1), Legendary 0.6(Lv-1).
- 쥬얼 종류는 5종 중 균등 랜덤.

## 5. 쥬얼 (Jewel)

- 쥬얼 하나하나가 종류·등급·레벨을 가진 독립 아이템임.
- 같은 종류·등급 쥬얼이 중복으로 나올 수 있음.
- 등급과 레벨은 쥬얼 자체 속성이라, 장착 위치를 바꿔도 유지됨.
- 합성 기능은 없음. 남는 쥬얼은 판매함.
- 비유하면 반지마다 강화 수치가 새겨져 있어서 어느 손가락에 끼든 수치가 따라다니는 구조임.

**종류 5종**

| 쥬얼 | 계열 | 효과 |
|---|---|---|
| Ruby | 양 | 채굴 1회당 토큰 고정값 증가 |
| Topaz | 양 | 채굴 1회당 토큰 % 증가 |
| Sapphire | 속도 | 자동 채굴 간격 감소 |
| Emerald | 운 | 일정 확률로 2배 채굴 |
| Diamond | 보조 | 같은 슬롯 안 다른 쥬얼 효과 증폭 |

- 쥬얼 효과는 자동 채굴과 타자 채굴 보상 모두에 적용함.
- 이유: 주 수입이 타자 채굴이라, 자동 채굴에만 적용하면 쥬얼이 무의미해짐.

**등급 4단계**

| 등급 | 효과 배율 | 기준 가치 | Lv.1 판매가 |
|---|---|---|---|
| Normal | x1 | 150 | 105 |
| Rare | x2 | 600 | 420 |
| Unique | x4 | 3,000 | 2,100 |
| Legendary | x8 | 15,000 | 10,500 |

**레벨**

- 모든 등급 공통 최대 Lv.10.
- 등급별 최대 레벨을 다르게 하지 않음. 고등급일수록 만렙이 늦어지는 역전 현상을 막기 위함.
- 레벨업 비용 = 800 x 2^(Lv - 1), 등급 무관.
- 쥬얼 1개 만렙까지 총 408,800 토큰.
- 쥬얼 효과 강도 = 0.4 x 등급 배율 x (1 + 0.25 x (Lv - 1)).
- 예: Normal Lv.10 = 1.3, Legendary Lv.10 = 10.4.
- 효과 강도를 종류별 효과 수치로 바꾸는 계수는 구현 후 밸런스 조정 대상임.

**판매**

- 판매가 = (기준 가치 + 누적 레벨업 비용) x 70%.
- 예: Normal을 Lv.2까지 올렸으면 (150 + 800) x 0.7 = 665.
- 장착 중인 쥬얼은 판매 불가.
- 각 쥬얼은 고유 id를 가짐. 슬롯은 쥬얼을 id로 참조함.

## 6. 인벤토리 (Inventory)

- 획득한 쥬얼은 전부 인벤토리에 들어감.
- 자동 장착 없음.
- 시작 5칸, 5칸씩 확장, 최대 50칸.

## 7. 슬롯 (Slot)

- 슬롯은 쥬얼을 담는 상자일 뿐, 자체 수입 효과 없음.
- 슬롯 없이 시작해서 토큰으로 구매함.
- 최대 3개.
- 슬롯 레벨이 칸 수임. Lv.1은 1칸, Lv.2는 2칸, Lv.3은 3칸.
- 최대 장착 쥬얼 9개 (3슬롯 x 3칸).
- 뒷번호 슬롯일수록 구매가와 레벨업 비용이 비쌈.

| 슬롯 | 구매 (1칸) | Lv.2 (2칸) | Lv.3 (3칸) |
|---|---|---|---|
| 1번 | 500 | 5,000 | 20,000 |
| 2번 | 20,000 | 60,000 | 160,000 |
| 3번 | 150,000 | 300,000 | 600,000 |

- 장착·해제는 Slots 화면에서 사용자가 직접 함.
- 해제한 쥬얼은 인벤토리로 돌아감.

## 8. 조합 (Combo)

- 슬롯 하나에 쥬얼 3개가 모두 찼을 때만 조합 판정함.
- 판정은 쥬얼 종류만 봄. 칸 순서는 무시함.
- 보너스 크기는 들어간 쥬얼들의 등급·레벨을 반영함.
- 슬롯당 조합 1개, 최대 3개 동시 적용.
- 5종 3칸 조합은 총 35가지이고, 그중 22개를 이름 있는 조합으로 지정함.
- 나머지 13개 조합은 쥬얼 기본 효과 합산만 적용함.
- 비유하면 포커 족보임. 모든 패가 족보는 아니고, 족보가 되면 보너스가 붙음.

## 9. 최종 목표 (Genesis Token)

**해금 조건 (전부 충족)**

- 자동 채굴 Lv.50
- 광산 Lv.10
- 슬롯 3개 모두 Lv.3
- 9칸 전부 Lv.10 쥬얼 장착
- 인벤토리 50칸

- 쥬얼 등급은 조건에 없음. 등급은 도달 시간에만 영향을 줌.
- 해금되면 메인 메뉴에 `[5] Genesis`가 나타남.
- 가격 500,000 토큰 (최종 상태 수입으로 약 30분 분량, 재조정 대상).

**첫 구매 시 엔딩**

- 타이틀 화면은 없음.
- 대신 첫 구매 시 화려한 텍스트 아트 + 크레딧을 보여줌.
- 크레딧은 아래에서 위로 한 줄씩 올라오는 영화 엔딩 연출.
- 웹 버전에서는 CSS/애니메이션으로 연출을 강화해도 됨. 단, 텍스트 아트 감성은 유지할 것.

**크레딧 구성**

```
[Genesis Token 코인 텍스트 아트, 일련번호 #0001]
```

## 10. 화면 / 메뉴 구조

```
Main (GENESIS TOKEN)
├── [1] Mine        타자 채굴, 광산 레벨업
├── [2] Slots       슬롯 구매·레벨업, 쥬얼 장착·해제
├── [3] Inventory   쥬얼 레벨업·판매, 인벤토리 확장
├── [4] Combos      조합 도감
├── [5] Genesis     최종 아이템 구매 (조건 달성 시 등장)
├── [u] Auto mine level up
├── [s] Settings    루팡용 사이트(Boss site) URL 설정
└── [q] Save & Quit
```

- 별도 Upgrade 메뉴는 없음. 각 레벨업은 해당 메뉴 화면에서 진행함.
- 메뉴를 선택하면 해당 화면으로 전환됨.
- 모든 목록 선택은 화살표 키로 함.
- 하위 화면에서 메인 복귀는 `b`.
- Mine 화면도 선택 모드(`Space` 전환)에서 `b`로 나감.
- Settings 화면: `e` URL 편집(`Enter` 저장, `Esc` 취소, 붙여넣기 가능), `d` 기본값 복원. `http://`, `https://`만 허용. 저장본과 별도 보관되어 새 게임 시작 시에도 유지됨.
- `Esc` 보스 키(루팡 사이트 새 탭 열기)는 보류 중임.
- 모든 화면 상단에 제목과 보유 토큰을 표시함.
- 하단에 직전 행동 결과 메시지를 표시함.

**메인 화면 표시 항목**

| 항목 | 내용 |
|---|---|
| Tokens | 보유 토큰 (천 단위 쉼표) |
| Auto mine | 레벨, 1회 채굴량 / 채굴 간격, 다음 레벨 비용 |
| Mine | 광산 레벨 |
| Slots | 보유 슬롯 수 / 3 |
| Inventory | 보유 쥬얼 수 / 칸 수 |
| Genesis | 보유 개수 (첫 구매 후 표시) |

**화면별 조작**

| 화면 | 위아래 | 좌우 | 키 |
|---|---|---|---|
| Main | - | - | `1`~`5` 메뉴, `u` 자동 채굴 레벨업, `s` 설정, `q` 저장 종료 |
| Mine | - | - | 타자 입력, `Enter` 제출, 광산 레벨업 키, `b` 뒤로 |
| Slots | 슬롯 선택 | 칸 선택 | `n` 슬롯 구매, `l` 슬롯 레벨업, `e` 장착, `r` 해제 |
| Inventory | 쥬얼 선택 | - | `l` 레벨업, `x` 판매, `e` 확장 |
| Combos | 스크롤 | - | `b` 뒤로 |
| Genesis | - | - | `Enter` 구매 |

**Slots 화면 예시**

```
=== SLOTS ===
Tokens: 54,200
> Slot 1 Lv.3  [Ruby] >[empty]< [empty]
  Slot 2 Lv.1  [empty]
  Slot 3 (locked)

Slot 1 level up: MAX
Buy next slot: 150,000
Combo: none
```

- 고른 칸은 `>[ ]<`처럼 강조함.
- 장착(`e`) 시 장착 가능한 쥬얼 목록을 띄우고 고르면 선택한 칸에 들어감.
- 현재 슬롯의 조합 성립 여부를 아래에 표시함.

**Inventory 화면 예시**

```
=== INVENTORY 7/10 ===
Tokens: 47,400
  #1  Topaz     Rare    Lv.4  [E]
> #2  Ruby      Normal  Lv.2
  #3  Sapphire  Unique  Lv.1

Level up: 1,600   Sell: 665
Expand +5: 2,000
```

- `[E]`는 장착 중 표시.
- 목록이 화면보다 길면 커서를 따라 스크롤함.

**Mine 화면 예시**

```
=== MINE Lv.3 ===
Tokens: 15,230
Type: aB3kQz
Input: aB3_

[Enter] Submit  [b] Back
+52 tokens!  Got Rare Topaz!
```

## 11. 저장 / 불러오기

- 보안(조작 방지)은 고려하지 않음. 혼자 하는 게임임.
- 사람이 읽기 쉬운 JSON 형식으로 저장함.
- 저장 위치는 기존 프로젝트 방식을 따를 것 (서버 JSON 파일 또는 브라우저 localStorage).

**저장 시점**

| 시점 | 이유 |
|---|---|
| Save & Quit | 기본 저장 |
| 30초마다 자동 | 브라우저·기기 강제 종료 대비 |
| 페이지 닫기 직전 | 실수로 닫은 경우 대비 |

- 불러오기 실패(파일 손상) 시 새 게임으로 시작하고 안내 메시지 표시.
- 저장 직전 이전 저장본을 백업 1개 유지.

**저장 데이터 분리**

| 데이터 | 저장 대상 | New game 시 |
|---|---|---|
| 토큰, 레벨, 쥬얼, 슬롯 | save | 초기화 |
| 조합 도감 | save | 초기화 |
| 플레이 통계 | save | 초기화 |
| 엔딩 횟수, 최단 기록, Genesis 총 개수 | records | 유지 |

- 비유하면 save는 이번 판 노트, records는 졸업장 보관함임.

**save 구조 예시**

```json
{
  "version": 1,
  "saved_at": 1762409820.5,
  "tokens": 15230.4,
  "auto_miner_level": 6,
  "mine_level": 3,
  "inventory_size": 10,
  "next_jewel_id": 3,
  "jewels": [
    {"id": 1, "kind": "Topaz", "grade": "Rare", "level": 4, "spent": 5600},
    {"id": 2, "kind": "Ruby", "grade": "Normal", "level": 1, "spent": 0}
  ],
  "slots": [
    {"level": 2, "equipped": [1, null]},
    {"level": 1, "equipped": [null]}
  ],
  "combos_found": ["Crimson Vein", "Trinity"],
  "genesis_owned": 0,
  "stats": {
    "play_time": 26640,
    "words_typed": 1203,
    "jewels_found": 21,
    "best_jewel": "Legendary Sapphire"
  }
}
```

- 쥬얼은 `jewels`에 한 번만 저장하고, 슬롯은 id만 기록함.
- `spent`는 누적 레벨업 비용이며 판매가 계산에 사용함.
- `play_time`은 게임이 켜져 있던 시간만 누적함.

**records 구조 예시**

```json
{
  "endings": 2,
  "best_clear_time": 15840,
  "total_genesis": 7
}
```

## 12. 밸런스 검증 기준

- 위 수치는 Python 시뮬레이션(각 200회)으로 맞춘 값임.
- 구현 후 같은 조건으로 시뮬레이션 스크립트를 만들어 재검증할 것.

| 구분 | 최고 운 | 상위 10% | 중간값 | 하위 10% |
|---|---|---|---|---|
| 보통 (하루 1시간 타자) | 4.4일 | 6.0일 | 7.0일 | 8.7일 |
| 빠름 (하루 2시간 타자) | 2.3일 | 3.2일 | 3.8일 | 4.8일 |

**시뮬레이션 가정**

- 타자 1회 소요 시간 = 2초 + 0.9초 x 문자열 길이.
- 오타율 10%.
- 쥬얼 효과는 "1 + 장착 쥬얼 효과 강도 합"을 모든 채굴량에 곱하는 단순 모델.
- 조합 보너스는 미반영. 조합 반영 후 플레이 시간이 줄어들 것이므로 재조정 필요.

## 13. 미결 사항

| 항목 | 내용 | 비고 |
|---|---|---|
| Sapphire 효과 | 자동 채굴 간격만 줄이면 타자 채굴 중심 구조에서 약함 | 대안: 타자 채굴 쥬얼 확률 증가로 변경 |
| 종류별 효과 계수 | 효과 강도를 실제 수치로 바꾸는 계수 미정 | 5종 체감 가치가 비슷하도록 조정 |
| 조합 보너스 수치 | 초안 상태 | 시뮬레이션 후 확정 |
| Genesis 가격 | 500,000 잠정 | 최종 수입 30분 분량으로 재계산 |

## 14. 구현 순서 제안
